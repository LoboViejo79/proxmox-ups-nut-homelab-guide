Apagado seguro de Proxmox con una UPS Hikvision DS-UPS2000-R y NUT

Guía completa, paso a paso y pensada para poder replicarse: la UPS alimenta el rack durante un corte, NUT espera 180 segundos, cancela el apagado si vuelve la energía y, si el corte continúa, ordena detener VM/LXC y apagar Proxmox sin enviar killpower a la UPS.

1. Qué problema resuelve este diseño

Una UPS por sí sola sólo mantiene los equipos encendidos durante un tiempo. El problema aparece cuando la batería se agota: si el hypervisor y sus máquinas siguen escribiendo datos, el corte final se parece a desenchufar el servidor. Este diseño transforma ese tiempo de batería en una ventana controlada de apagado.

180 s

Tolerancia a microcortes

Durante los primeros tres minutos el servidor sigue trabajando. Si la red vuelve antes del umbral, el temporizador se cancela.

OB → FSD

Decisión verificada

Al vencer el timer se vuelve a consultar ups.status. Sólo si continúa en batería se solicita FSD.

0

Killpower

La política deliberada es apagar Proxmox, pero dejar la UPS alimentando otros equipos esenciales.

Idea centralEl objetivo no es “apagar todo cuanto antes”, sino proteger la integridad de datos y servicios sin desperdiciar batería en cortes breves.

2. Arquitectura recomendada

NUT se ejecuta directamente en el nodo Proxmox. La conexión USB no se pasa a una VM ni a un LXC: el propio hypervisor conserva la autoridad de apagado incluso si un guest falla.

4. Seguridad antes de tocar la configuración

Comandos destructivosupsmon -c fsd, systemctl poweroff, qm stop y cualquier mecanismo de killpower pueden apagar equipos reales. No se deben usar como comandos de consulta.

La forma segura de implementar esto es por fases. Primero lectura, después autenticación, luego simulación de shutdown, después temporizador y sólo al final se reemplaza el shutdown simulado por el poweroff real.

Lección prácticaNo pegues líneas sueltas extraídas del interior de un bloque case ... esac. Una línea como /usr/sbin/upsmon -c fsd se ejecuta por sí sola aunque el resto del fragmento produzca errores de sintaxis.

Reglas para una prueba segura

  • Tener acceso físico o consola fuera de banda antes de probar apagados.
  • Hacer backup de /etc/nut.
  • Confirmar que el shutdown inicial apunta al script de simulación.
  • No usar upsdrvctl shutdown en este diseño.
  • Realizar la prueba real en una ventana de mantenimiento.

5. Glosario

NUT
Network UPS Tools: suite que comunica el sistema operativo con UPS/SAI.
UPS / SAI
Sistema de alimentación ininterrumpida.
usbhid-ups
Driver NUT para dispositivos USB HID compatibles.
upsd
Servidor de NUT que publica variables y recibe clientes autorizados.
upsc
Cliente de consulta para leer variables de una UPS publicada por upsd.
upsmon
Monitor que interpreta el estado eléctrico y puede iniciar el shutdown.
upssched
Programador de acciones y temporizadores asociado a eventos de upsmon.
OL
On Line: hay red eléctrica.
OB
On Battery: la carga está siendo alimentada por batería.
LOWBATT
Estado crítico de batería. En esta política solicita FSD inmediatamente.
FSD
Forced Shutdown: señal coordinada de NUT para iniciar apagado.
POWERDOWNFLAG
Bandera que puede participar en la fase de cortar energía de la UPS. Aquí se omite deliberadamente.
sdorder=-1
Configuración usada para excluir esta UPS de una secuencia de shutdown del driver.
pve-guests
Servicio Proxmox que arranca/detiene los guests del nodo.
startup order
Orden de inicio configurado por guest. El apagado se realiza en orden inverso.
QEMU Guest Agent
Agente dentro de una VM que permite a Proxmox coordinar acciones y consultar su estado.
udev
Subsistema Linux que aplica permisos/reglas a dispositivos cuando aparecen.
systemd
Gestor de servicios usado por Proxmox/Debian para NUT y el propio apagado.

6. Prerrequisitos

Proxmox/Debian

Acceso root, systemd operativo y una ventana de mantenimiento para la prueba final.

UPS por USB

Hikvision DS-UPS2000-R conectada directamente al host. En el laboratorio se identificó como 0463:0001 MGE UPS Systems UPS.

Instalar paquetes
apt update
apt install -y nut nut-client nut-server usbutils

Por qué: nut-server aporta upsd; nut-client contiene herramientas como upsc/upsmon; usbutils aporta lsusb.

Backup antes de empezar

mkdir -p /root/backup-nut
cp -a /etc/nut /root/backup-nut/nut-$(date +%F-%H%M%S)

7. Paso 1 — detectar la UPS por USB

Enumerar dispositivos.
lsusb
Busca una línea similar a ID 0463:0001 MGE UPS Systems UPS.
Pedir a NUT que sugiera driver.
nut-scanner -U
El resultado observado propuso driver = "usbhid-ups", vendorid = "0463" y productid = "0001".
Verificar el kernel.
dmesg -T | grep -Ei 'usb|hid|ups' | tail -n 100
Sirve para comprobar que el dispositivo HID aparece y que el problema no está en el cable/puerto.
Mensajes auxiliares de nut-scannerAdvertencias por módulos SNMP/XML/IPMI ausentes no impiden este escenario USB local si el escaneo USB funciona.

8. Paso 2 — configuración base de NUT

/etc/nut/ups.conf

maxretry = 3

[ups-rack]
    driver = usbhid-ups
    port = auto
    vendorid = 0463
    productid = 0001
    sdorder = -1
    desc = "Hikvision DS-UPS2000-R Rack"

Qué significa cada línea: driver selecciona el controlador; port=auto evita fijar un número de bus USB que puede cambiar; vendor/product limitan el dispositivo esperado; sdorder=-1 refuerza la política de no cortar la UPS.

/etc/nut/nut.conf

MODE=standalone

En standalone, driver, servidor NUT y monitor viven en la misma máquina. Para este caso es más simple y reduce dependencias externas.

9. Paso 3 — permisos USB y udev

Un error típico es:

libusb1: Could not open any HID devices: insufficient permissions on everything
No matching HID UPS found

Antes de inventar reglas nuevas, verifica las que ya instala el paquete:

grep -Ri '0463' /usr/lib/udev/rules.d/ /etc/udev/rules.d/ 2>/dev/null

En el laboratorio ya existía una regla que asociaba 0463:0001 al grupo nut. Se recargó así:

udevadm control --reload-rules
udevadm trigger --subsystem-match=usb --action=change
sleep 3
lsusb | grep 0463

Para comprobar el nodo concreto de dispositivo puedes usar ls -l /dev/bus/usb/BBB/DDD después de localizarlo con lsusb. El resultado esperado es grupo nut.

No hardcodear /dev/bus/usb/001/005Los números de bus/dispositivo cambian al reconectar o reiniciar. Por eso NUT usa port=auto y los IDs USB.

10. Paso 4 — iniciar el driver y servicios systemd

En la instalación original, upsdrvsvcctl list no enumeró correctamente la instancia aunque systemd sí la conocía. Se administró directamente la unidad:

systemctl reset-failed nut-driver@ups-rack.service
systemctl start nut-driver@ups-rack.service
systemctl status nut-driver@ups-rack.service --no-pager -l

Mensajes de éxito observados:

Publicar datos con upsd

12. Paso 6 — crear el usuario interno de monitoreo

NUT necesita una credencial local para que upsmon se autentique contra upsd. No reutilices la contraseña de root ni la de la interfaz web.

MONPASS="$(openssl rand -hex 24)"
printf '%s\n' '[upsmon]' \
  "    password = $MONPASS" \
  '    upsmon primary' \
  > /etc/nut/upsd.users
chmod 640 /etc/nut/upsd.users
chown root:nut /etc/nut/upsd.users
ImportanteGuarda esa contraseña temporalmente para colocar exactamente el mismo valor en la línea MONITOR de upsmon.conf. El ZIP público contiene únicamente <PASSWORD_UPSMON>.

13. Paso 7 — configurar un shutdown simulado

Antes de permitir un poweroff real, crea un script que sólo escriba en el journal.

cat > /usr/local/sbin/nut-shutdown-sim.sh <<'EOF'
#!/bin/sh
logger -t NUT-SIM "SIMULACION: NUT habria iniciado el apagado de Proxmox"
exit 0
EOF
chown root:nut /usr/local/sbin/nut-shutdown-sim.sh
chmod 750 /usr/local/sbin/nut-shutdown-sim.sh

upsmon.conf — fase de laboratorio

RUN_AS_USER nut
MONITOR ups-rack@localhost 1 upsmon  primary
MINSUPPLIES 1
SHUTDOWNCMD "/usr/local/sbin/nut-shutdown-sim.sh"
POLLFREQ 5
POLLFREQALERT 5
HOSTSYNC 15
DEADTIME 15
RBWARNTIME 43200
NOCOMMWARNTIME 300
FINALDELAY 5
Criterio de salida de esta faseAntes de seguir, nut-monitor debe permanecer estable y una prueba FSD manual debe generar sólo el mensaje NUT-SIM, sin apagar ninguna VM ni el host.

14. Paso 8 — añadir upssched

upsmon detecta eventos. upssched aporta memoria temporal: “si sigue en batería dentro de 180 segundos, ejecuta otra acción; si vuelve la luz, cancela”.

Crear el directorio volátil correctamente en cada arranque

cat > /etc/tmpfiles.d/nut-upssched.conf <<'EOF'
d /run/nut/upssched 0750 nut nut -
EOF
systemd-tmpfiles --create /etc/tmpfiles.d/nut-upssched.conf

/etc/nut/upssched.conf

CMDSCRIPT /usr/local/sbin/nut-upssched-cmd
PIPEFN /run/nut/upssched/upssched.pipe
LOCKFN /run/nut/upssched/upssched.lock

AT ONBATT * EXECUTE onbatt
AT ONBATT * START-TIMER onbatt-long 180
AT ONLINE * CANCEL-TIMER onbatt-long
AT ONLINE * EXECUTE online
AT LOWBATT * EXECUTE lowbatt
AT COMMBAD * START-TIMER commbad-long 120
AT COMMOK * CANCEL-TIMER commbad-long
AT COMMOK * EXECUTE commok
AT NOCOMM * EXECUTE nocomm

Conectar eventos de upsmon

NOTIFYCMD /usr/sbin/upssched
NOTIFYFLAG ONLINE SYSLOG+EXEC
NOTIFYFLAG ONBATT SYSLOG+EXEC
NOTIFYFLAG LOWBATT SYSLOG+EXEC
NOTIFYFLAG COMMBAD SYSLOG+EXEC
NOTIFYFLAG COMMOK SYSLOG+EXEC
NOTIFYFLAG NOCOMM SYSLOG+EXEC

La pérdida de comunicación USB no dispara un shutdown automático en esta política: primero se espera 120 s y sólo se registra una alerta. Esto evita apagar por un problema aislado de cable/USB.

15. Paso 9 — script de decisión completo

Este es el script final usado por la automatización. Su detalle importante es que no confía ciegamente en que el timer venció: vuelve a leer el estado.

/usr/local/sbin/nut-upssched-cmd
#!/bin/sh

ACTION="$1"
UPS="ups-rack@localhost"

case "$ACTION" in
    onbatt)
        logger -t NUT-SCHED "UPS entro en bateria. Temporizador de seguridad de 180 segundos iniciado."
        ;;
    online)
        logger -t NUT-SCHED "Energia restaurada. UPS nuevamente ONLINE."
        ;;
    onbatt-long)
        STATUS="$(/usr/bin/upsc "$UPS" ups.status 2>/dev/null || true)"
        logger -t NUT-SCHED "Temporizador de 180 segundos cumplido. Estado actual UPS: ${STATUS:-DESCONOCIDO}"
        case "$STATUS" in
            *OB*)
                logger -t NUT-SCHED "UPS sigue en bateria despues de 180 segundos. Solicitando FSD a NUT."
                /usr/sbin/upsmon -c fsd
                ;;
            *OL*)
                logger -t NUT-SCHED "FSD cancelado: UPS ya esta ONLINE."
                ;;
            *)
                logger -t NUT-SCHED "ADVERTENCIA: estado UPS desconocido. No se ejecuta FSD por temporizador."
                ;;
        esac
        ;;
    lowbatt)
        logger -t NUT-SCHED "EMERGENCIA: UPS reporta LOWBATT. Solicitando FSD inmediato."
        /usr/sbin/upsmon -c fsd
        ;;
    commbad-long)
        logger -t NUT-SCHED "ALERTA: comunicacion con UPS perdida durante 120 segundos."
        ;;
    commok)
        logger -t NUT-SCHED "Comunicacion con UPS restaurada."
        ;;
    nocomm)
        logger -t NUT-SCHED "ALERTA: UPS no disponible para NUT."
        ;;
    *)
        logger -t NUT-SCHED "Evento desconocido recibido: $ACTION"
        ;;
esac
exit 0
install -o root -g nut -m 0750 configs/nut-upssched-cmd /usr/local/sbin/nut-upssched-cmd
sh -n /usr/local/sbin/nut-upssched-cmd
Diseño fail-safeSi la lectura de estado falla o devuelve algo que no contiene OB/OL, el timer no dispara FSD. LOWBATT sigue teniendo su ruta de emergencia independiente.

17. Paso 11 — pasar a producción

Sólo después de superar todas las pruebas simuladas cambia el comando de apagado:

# /etc/nut/upsmon.conf
SHUTDOWNCMD "/usr/bin/systemctl poweroff"

Mantén los mismos eventos de upssched. La política queda:

Corte normal

ONBATT → espera 180 s → vuelve a comprobar OB → FSD → apagado.

Batería crítica

LOWBATT → FSD inmediato. No se espera el timer.

Reiniciar y comprobar

systemctl restart nut-server
systemctl restart nut-monitor
systemctl is-active nut-driver@ups-rack.service nut-server nut-monitor
upsc ups-rack@localhost ups.status

18. Política eléctrica — apagar Proxmox, no la UPS

# /etc/nut/upsmon.conf
SHUTDOWNCMD "/usr/bin/systemctl poweroff"
# Deliberadamente NO existe POWERDOWNFLAG

# /etc/nut/ups.conf
sdorder = -1

El resultado deseado es que el servidor deje de consumir batería, pero que la UPS siga entregando AC a equipos como router, switch, AP y ONT/módem (si también están conectados a ella).

Red local no significa InternetMantener router/switch/AP encendidos conserva LAN y Wi‑Fi. Para tener salida a Internet durante el apagón, también debe seguir alimentado el equipo del ISP y el proveedor debe mantener servicio aguas arriba.

20. FSD controlado y recuperación de laboratorio

Con SHUTDOWNCMD todavía apuntando al script de simulación, puede probarse:

runuser -u nut -- /usr/sbin/upsmon -c fsd

El journal debería mostrar que NUT recibió el FSD y ejecutó el shutdown automático, pero en lugar de apagar se ejecutará NUT-SIM.

Limpiar el estado FSD después de una prueba

systemctl stop nut-monitor
rm -f /run/nut/killpower
systemctl restart nut-server
sleep 3
upsc ups-rack@localhost ups.status
# Debe volver a OL si hay red
systemctl restart nut-monitor
No hagas esta prueba después de cambiar a poweroff real salvo que quieras apagar el hostUna vez que SHUTDOWNCMD es systemctl poweroff, FSD es una orden de apagado real.

23. Qué pasa cuando vuelve la energía

Esta arquitectura tiene una consecuencia importante: como la UPS no corta físicamente AC a la fuente del servidor, después del poweroff la PSU puede seguir viendo tensión durante todo el apagón. Por tanto, una opción BIOS del tipo “Restore on AC Power Loss” no necesariamente verá una nueva transición de OFF→ON cuando vuelva la red.

WOL

Un router, mini-PC u otro equipo que siga encendido puede enviar Wake-on-LAN.

IPMI/BMC

En hardware de servidor, un BMC permite encender el host fuera de banda.

Control externo

Un dispositivo independiente puede detectar ONLINE y ejecutar la acción de encendido.

No automatizado en este manualEl apagado seguro está validado; el encendido automático debe diseñarse aparte porque depende del hardware disponible.
